# Classifier Outputs

Classifier outputs are generated by:

- `scripts/07_train_classifier.R` for complete training-genome sanity checks.
- `scripts/08_classify_partials.R` for external partial FASTA records.

A resolved classification is a thresholded interpretation of observed SNP evidence. It is not automatically correct and should be checked against validation summaries, mapping diagnostics, classifier support, conflict, and biological context. Do not confuse this later-stage support with MCC posterior support or SNP `gain` / `normalized_gain`.

## Complete-Genome Classifier Outputs

| File | Meaning | Key columns |
|---|---|---|
| `outputs/models/wssv_classifier.rds` | Saved classifier object used by partial classification. | R object; inspect with R only. |
| `outputs/tables/classifier_training_summary.csv` | Overall training-set sanity-check counts. | `tips_checked`, `resolved`, `weak_support`, `conflicting`, `unresolved`, means for observed sites and off-path classifier support. |
| `outputs/tables/classifier_tip_predictions.csv` | One row per complete training genome. These are not independent validation results. | `query_id`, `assigned_node`, `assigned_support`, `support_margin`, `status`, `conflict_reason`, `on_path_nodes_supported`, `off_path_nodes_supported`. |
| `outputs/tables/classifier_node_evidence.csv` | Optional node-level evidence when compact enough. | `query_id`, `node_id`, `observed_sites`, `support_sites`, `conflict_sites`, `support`, `conflict`. |

## Partial-Genome Outputs

| File | Meaning | Key columns |
|---|---|---|
| `partial_classifications.csv` | Final harmonised partial classifications. In `auto` mode, this may combine panel calls with opportunistic fallback. | `sequence_id`, `mapped`, `classification_source`, `alignment_start`, `alignment_end`, `observed_informative_sites`, `assigned_node`, `assigned_support`, `support_margin`, `status`, `reason`. |
| `partial_classifications_panel.csv` | Panel-only partial classifications. | Same main classification columns. |
| `partial_classifications_opportunistic.csv` | Opportunistic classifications using scored SNPs in each mapped interval. | Same main classification columns; `resolved_opportunistic` indicates opportunistic resolution. |
| `partial_node_evidence.csv` | Panel node evidence, usually for resolved, weak, or conflicting records unless unresolved evidence is enabled. | Node support/conflict counts and weights. |
| `partial_opportunistic_node_evidence.csv` | Node evidence for opportunistic partial calls. | `node_id`, `support`, `conflict`, site counts. |
| `partial_opportunistic_site_evidence.csv` | Site-by-node evidence for opportunistic calls. | `alignment_site`, node/rule columns, support or conflict indicators. |
| `partial_opportunistic_site_summary.csv` | Record-level summary of opportunistic site evidence. | `assigned_status`, `unique_observed_scored_sites`, `off_path_supporting_sites`, `interpretation`. |
| `partial_region_diagnostics.csv` | Mapping interval and evidence availability diagnostics. | `mapped`, `alignment_start`, `alignment_end`, `sites_available_in_region`, `sites_observed`, `observed_non_missing_sites`. |

## Key Terms In Output Statuses

| Term | Meaning |
|---|---|
| `resolved` | The classifier found a supported node/path that passed classifier support, conflict, and margin thresholds. Check evidence before trusting it. |
| `resolved_opportunistic` | A partial genome was resolved using scored SNPs available in its mapped interval, not necessarily the designed panel. Treat as region-dependent evidence. |
| `weak_support` | Some evidence was present, but it did not pass classifier support, margin, or minimum observed-site thresholds. |
| `conflicting` | Strong evidence supports incompatible nodes or a close incompatible competitor. |
| `unclassified` | General plain-language label for records without a resolved assignment; exact status may be `weak_support`, `conflicting`, `unmapped`, `no_informative_sites`, or `no_observed_informative_sites`. |
| `unmapped` | The partial sequence could not be placed onto alignment coordinates with the configured mapping method and thresholds. |
| `no_informative_sites` | The mapped region contains no scored informative SNPs. |
| `no_observed_informative_sites` | Informative SNPs exist in the region, but the query has missing, ambiguous, or gapped states at those sites. |
| Missing | Encoded as base code `0` internally for gaps, ambiguous bases, or absent sequence. Missing evidence cannot support a node. |
| Compatible support | Supported nodes are nested on one tree path, so they can describe the same ancestry path. |
| Conflicting evidence | Evidence supports incompatible branches that cannot both be on the same path. |
| Off-path support | For training genomes, classifier support for nodes not on the known MCC path for that tip. In partials, site summaries may also flag support outside the assigned path. |
| Partial-genome classification | Classification from incomplete sequence data. It depends strongly on mapping quality and which informative sites are observed. |

## Conservative Versus Over-Permissive Settings

Conservative settings usually show:

- Some weak or unclassified calls when evidence is sparse.
- Few `conflicting` calls.
- Resolved calls with adequate `observed_informative_sites`, high `assigned_support`, and acceptable `support_margin`.
- Partial records with clear mapping diagnostics.

Over-permissive settings may show:

- Nearly every partial record resolved, including records with one observed site.
- Low support margin between competing nodes.
- Many resolved calls despite high `conflict_sites` or off-path classifier support.
- Opportunistic calls replacing many panel failures without clear explanation.

Overly strict settings may show:

- Many `weak_support` calls despite good mapping and several observed informative sites.
- Very few classifiable nodes after training.
- Validation summaries with low resolved fractions for all panel sizes.

## Warning Signs

- `resolved` calls with `observed_informative_sites` equal to 1 should be treated cautiously.
- High `off_path_nodes_supported` in `classifier_tip_predictions.csv` suggests parameter settings may be too permissive or markers are not specific enough.
- Many `conflicting` calls can mean thresholds are too permissive, windows include mixed signals, or the data contain recombination/error/ambiguous signal.
- Many `unmapped` partials point first to formatting, orientation, or mapping-threshold issues.
